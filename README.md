# پنل سانا — قالب پنل مدیریتی ماژولار

سامانه اعتباری نوید امید (سانا) — طرح نگین میثاق، روی یک **هسته قابل استفاده مجدد** ساخته شده است.
همین مخزن را می‌توان برای پروژه دیگری کلون کرد یا فلوهای جدید (غیر از سانا) را به آن اضافه کرد.

**استک:** React 19 · TypeScript · Vite 8 · Ant Design 6 (RTL + fa_IR) · React Hook Form · Yup · TanStack Query 5 · React Router 7 · Zustand · Recharts · ExcelJS · Vitest

## اجرا

```bash
npm install
npm run dev        # http://localhost:5173 — داده نمونه خودکار ساخته می‌شود
npm test           # تست‌های واحد + تست قواعد معماری
npm run build
```

در صفحه ورود، با «ورود سریع» با هر نقش وارد شوید (admin/admin یا کاربران نمونه با رمز `123456`).
مدیر سامانه از منوی کاربری (بالا-چپ) می‌تواند «بازنشانی داده‌های نمونه» بزند.

| متغیر `.env` | پیش‌فرض | کاربرد |
|---|---|---|
| `VITE_DEMO_DATA` | `true` | `false` = شروع با سامانه خالی |
| `VITE_EXAMPLE_MODULE` | `false` | `true` = فعال‌سازی ماژول نمونه «اطلاعیه‌ها» |
| `VITE_MOCK_DELAY` | `150` | تأخیر شبیه‌سازی‌شده API (ms) |

## ساختار

```
src/
  core/                 ← هسته عمومی؛ هیچ چیزی از «سانا» نمی‌داند
    config/             AppConfig + configureApp
    module/             سیستم ماژول: AppModule، رجیستری منو/مسیر/مجوز
    data/               Mock store عمومی (تراکنشی، گزارش تغییرات، بازگردانی) + هویت (کاربر/نقش/لاگ)
    auth/               نشست، usePermissions، Guardها، صفحه ورود
    query/              QueryClient با نمایش سراسری خطا، useApiMutation
    layout/             AppShell: منوی جمع‌شونده، منوی موبایل، breadcrumb، منوی کاربر
    router/             ساخت خودکار مسیرها از ماژول‌ها
    ui/                 کیت کامپوننت‌های عمومی (پایین را ببینید) — نمودارها: core/ui/charts
    form/               فیلدهای RHF+antd، FormDrawer/FormModal
    theme/              تم antd + متغیرهای CSS از روی رنگ‌های پروژه
    lib/                تاریخ شمسی، ارقام فارسی، مبلغ به حروف، اکسل، اعتبارسنج‌ها، uid
  modules/
    admin/              عمومی: مدیریت کاربران، ماتریس دسترسی نقش‌ها، گزارش تغییرات
    sana/               فلوی سانا: types، domain (منطق اعتبار)، api، queries، components، pages
    example/            الگوی یک فلوی جدید (CRUD اطلاعیه‌ها) — پیش‌فرض غیرفعال
  app/                  ← تنها بخش مخصوص پروژه
    config.ts           نام، لوگو، رنگ‌ها، نقش‌ها و دسترسی پیش‌فرض، کاربران نمونه، پیشوند storage
    modules.ts          فهرست ماژول‌های فعال (ترتیب = ترتیب گروه‌های منو)
  main.tsx
```

**قواعد وابستگی** (با `src/core/__tests__/architecture.test.ts` در CI چک می‌شود):

- `core` ← هیچ‌چیز از `modules` یا `app` import نمی‌کند.
- هر ماژول ← فقط از `core` و خودش؛ ماژول‌ها همدیگر را نمی‌شناسند.
- `app` ← همه را کنار هم می‌گذارد.

## 🧬 استفاده برای پروژه دیگر

1. مخزن را کلون کنید.
2. `src/app/config.ts`: نام، لوگو (`public/img`)، رنگ‌ها، `storagePrefix`، `orgUnitLabel` (مثلاً «دپارتمان»)، نقش‌ها و کاربران نمونه.
3. `src/modules/sana` را حذف کنید و ماژول(های) خودتان را بسازید (بخش بعد).
4. `src/app/modules.ts` را به‌روز کنید.

`core` و `modules/admin` (کاربران، نقش‌ها، گزارش تغییرات، ورود، چیدمان، کامپوننت‌ها) بدون تغییر کار می‌کنند.

## ➕ افزودن یک فلوی جدید

پوشه `src/modules/example` را کپی کنید؛ سه فایل دارد:

```ts
// api.ts — داده (بعداً فقط همین فایل با HTTP واقعی جایگزین می‌شود)
const store = createMockStore('tickets', () => ({ tickets: [] as Ticket[] }))
export const ticketsApi = {
  list: () => store.query((s) => s.tickets),
  create: (input) => store.mutate((s, { actor, log }) => { /* ... */ log('TICKET', 'ثبت تیکت') }),
}

// TicketsPage.tsx — Page + SectionCard + DataTable + FormDrawer

// index.tsx — تعریف ماژول
export const ticketsModule: AppModule = {
  key: 'tickets',
  title: 'تیکت‌ها',
  pages: [{ path: 'tickets', title: 'تیکت‌ها', icon: <InboxOutlined />, group: 'پشتیبانی', component: lazy(() => import('./TicketsPage')) }],
  permissions: [{ key: 'tickets', label: 'تیکت‌ها', services: [['view', 'مشاهده'], ['edit', 'ویرایش']] }],
  auditCategories: [{ value: 'TICKET', label: 'تیکت', color: 'blue' }],
}
```

سپس در `app/modules.ts` اضافه کنید. **خودکار** ساخته می‌شوند: آیتم منو، مسیر با Guard دسترسی، ستون‌های ماتریس دسترسی نقش‌ها، دسته فیلتر در گزارش تغییرات، و امکان «بازگردانی» برای تغییراتی که snapshot دارند.
برای دادن دسترسی پیش‌فرض، کلید ماژول را به `defaultPerms` نقش‌ها در `config.ts` اضافه کنید (`'tickets'` = همه عملیات، `'tickets.view'` = فقط مشاهده).

## R&D — تصمیم‌ها و پیشنهادها

### معماری

| تصمیم | چرا / جایگزین |
|---|---|
| **core / modules / app** با قاعده وابستگی تست‌شده | قالب قابل کلون؛ فلوهای مستقل؛ جلوگیری از «چسبیدن» کد پروژه به هسته در طول زمان |
| ماژول = داده‌ای که منو، مسیر، مجوز و دسته لاگ را توصیف می‌کند | افزودن فلو بدون دست زدن به هسته. جایگزین: monorepo با پکیج جدا برای core (Nx/Turborepo) — وقتی چند پروژه هم‌زمان از هسته استفاده کنند ارزشش را دارد |
| هر ماژول store داده خودش را دارد | استقلال کامل؛ حذف یک ماژول، داده دیگری را خراب نمی‌کند |
| گزارش تغییرات و بازگردانی در هسته، عمومی بر اساس `{store, collection, id, before}` | هر ماژول فقط `log(..., snapshot)` صدا می‌زند |
| نقش ادمین همیشه همه دسترسی‌ها را دارد | جلوگیری از قفل شدن سامانه |

### فرم و داده

| تصمیم | چرا / جایگزین |
|---|---|
| RHF مالک state؛ antd فقط UI | ترکیب store فرم antd با RHF = دو منبع حقیقت |
| `yup.InferType` + `context` برای اعتبارسنجی وابسته به داده | تایپ از اسکیما؛ مثل «سقف اعتبار» یا «حداکثر طرح» |
| ارقام فارسی در yup `transform` لاتین می‌شوند | کاربر `۰۹۱۲…` تایپ می‌کند |
| کد ملی / شناسه ملی با رقم کنترل | نسخه HTML اعتبارسنجی نداشت |
| خطاهای Query/Mutation به‌صورت سراسری نمایش داده می‌شوند | هیچ خطایی بی‌صدا به «جدول خالی» تبدیل نمی‌شود |
| `uid()` با fallback به جای `crypto.randomUUID` | randomUUID روی `http://IP` (غیر localhost) وجود ندارد — باعث «نمایش ندادن داده» در شبکه بود |
| storeهای ماندگار بعد از `configureApp` hydrate می‌شوند | کلیدشان به پیشوند پروژه وابسته است |

### UX

صفحات با عنوان و توضیح؛ منوی جمع‌شونده با حالت ماندگار و Drawer در موبایل؛ ورود سریع با نقش‌ها در دمو؛ تب‌ها با شمارنده (تأییدها)؛ نوار عملیات گروهی؛ نوار چسبان ذخیره و هشدار ترک صفحه؛ هشدار بستن فرم ذخیره‌نشده؛ اطلاعات پایه در تب‌ها با نشان تعداد خطا روی هر تب؛ تخصیص وام سه‌مرحله‌ای با کارت‌های طرح و خلاصه چسبان + نوار پیشرفت سقف اعتبار؛ جستجوی جدول با نرمال‌سازی فارسی؛ ستون‌های چسبان با مقادیر منطقی `start/end` (RTL)؛ بدون اسکرول افقی در موبایل.

### 🐞 باگ‌های نسخه HTML که اصلاح شد

1. مدیر شرکت نمی‌توانست درخواستی را رد کند (فیلد دلیل مخفی ولی اجباری بود).
2. درخواست ردشده توسط مدیر شرکت هنوز اعتبار مصرف می‌کرد.
3. یک درخواستِ ردشده مانده انباشته ماه بعد را قفل می‌کرد.
4. ارجاع با نام پرسنل و ایندکس آرایه (هم‌نامی / حذف = خرابی داده) → شناسه یکتا.
5. XSS با `innerHTML`؛ `prompt()` برای علت عدم اعطا؛ فیلتر ماه رتبه‌بندی که هیچ‌وقت پر نمی‌شد.

### ⚠️ الزامات بک‌اند واقعی

- رمز عبور hash (argon2/bcrypt)؛ توکن در کوکی `httpOnly`.
- کنترل دسترسی روی هر endpoint (`usePermissions` فقط UX است).
- تاریخ مبنای تخصیص وام از ساعت سرور (فیلد تاریخ در صفحه فقط برای تست است).
- تراکنش/قفل برای برداشت هم‌زمان از یک اعتبار؛ مبالغ `BIGINT`/`DECIMAL`.
- آپلود فایل multipart + object storage (الان فقط نام فایل ذخیره می‌شود).
